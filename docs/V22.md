# V22 / production Recovery11 — native bag recovery and cutscene UI isolation

The owner confirms cross-player backpack closing persists after Recovery10/V21. Also reports immediate cutscene crashes with a castable wand and elemental book equipped. Latest local report is `2026-11-09 12.02.13 c676eebc`: ACCESS_VIOLATION, failed read 0xFFFFFFFFFFFFFFFF, Warcraft 3.0.1 build24371; log identifies Current Test/FFERPG-0.9.7.5g-Recovery10.w3x. Crash/log copies are in V22/evidence. The native stack does not attribute a JASS function or establish a network-desync cause.

## Bound native pane workaround

The existing observer records the actual gear/bag/backdrop handles only after seeing both content panes open for the selected own hero, outside inspection and cinematics. If they unexpectedly disappear while the player's own open intent remains true, it can show that exact previously verified pair again, at most once per second. It does not find or adopt new contexts in the recovery branch, recreate frames, send B, issue commands, read items or rebind inventory.

Explicit B close clears recovery authorization. X/ESC/close and saved-game panel reset clear its cached hero/frames. The existing selection/ownership/inspection and cinematic gates prevent recovery in those contexts. A 200ms existing input-settle interval prevents observing a delayed B close from immediately turning it into an open request again. The V21 partial-pane/anchor correction is retained.

This is an engine-behavior workaround candidate, not an established engine repair. The same cross-player closure was reported independently in Blizzard's PTR forum (Sep27 post86) and Hive; no verified workaround was reported there. See [first-hand Blizzard forum report](https://us.forums.blizzard.com/en/warcraft3/t/new-300-ptr-build-24306/39295?page=5) and docs/NATIVE_INVENTORY_MULTIPLAYER.md. The clean two-player diagnostic-map result remains unknown. Confirm in multiplayer that restored panes keep normal tooltips, dragging, item use and cooldown bindings; script mocks cannot establish native binding behavior.

## Cutscene candidate

The F/G cooldown renderer created normal-frame STATUSBAR widgets with an animated UI-Cooldown-Indicator model, parented to GAME_UI and anchored to simple-frame gear buttons. These were outside the hidden gear root and were not explicitly hidden by C20_HideUI. That is a source-confirmed omission; the crash report does not prove it was the crash cause.

These animated widgets are no longer created. The existing simple-frame overlay instead uses the 65 radial shadow textures already shipped in the map. It reads the same cooldown deadline/duration, changes texture only when its step changes, and retains numeric countdowns. No extra timer, frame or asset is added. The former model handle stays null for existing reset compatibility. The cinematic hide routine explicitly hides any legacy wheel handle as a defensive measure and clears the error/hover/pending-input presentation state.

Remaining gear hover/command/Calculator/spell-observer/icon-repaint/draw callbacks now gate before native getters while cinematic flags are set. V20's existing timer/gear-event/profile pause and post-cinematic resume remain unchanged. No wait or change to scene dialogue/cameras/timing is added.
