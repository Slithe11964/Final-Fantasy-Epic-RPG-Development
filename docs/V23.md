# Recovery10-based cinematic shutdown — V23 / Recovery12

The owner rejected Recovery11's automatic pane recovery and renderer replacement. This build starts from production Recovery10 and development V21, not Recovery11/V22. Both rejected changes are absent. Existing native cooldown models, icon repainting, Backpack observer/close/toggle behavior and all development content are preserved. Classic uses its unchanged Recovery09 baseline plus the shared polling pause changes.

## Common cutscene boundary

The existing common Cine_Enter is the only actual cinematic HUD entry in the map. More than 300 scene/dialogue actions call it, including the generic quest dialogue path. Its shared flags, profile capture/poll pause, gear/inventory UI timer pause, equipment event suspension, deferred cooldown pause and main stat/hero refresh timer pause already precede unit pausing and selection changes. No cutscene text, camera, timing, wait, reward or boss script is replaced.

This pass completes that shutdown:

- Disable the existing 22 gear input/UI/observer triggers, preserving which were enabled. This includes F/G click/key/mouse/sync/chat, wave/Calculator commands, gear hover, Backpack controls and Talents controls. Restore only the previously enabled triggers after the scene.
- Disable both F/G buttons and hide their root, simple buttons, texture overlays **and their separately parented native cooldown model widgets**. The models and renderer remain allocated and unchanged; they are not displayed during the scene. Restore each button's previous enabled state and let the normal UI heartbeat redraw against the current selection/cooldown state afterward.
- Hide every allocated gear preview image and all water/ice rune pools regardless of the current preview-mode flag. Hide custom targeting/error displays and clear pending input so a pre-scene click cannot cast after the scene.
- Pause the existing Chronicle inventory polling timer and shield-display polling timer. The anonymous Chronicle timer is now retained in a variable; the number of timers created is unchanged.
- Stop a queued passive/stat-change callback from restarting the stat timer while cinematic flags are set. Mark a shared dirty bit instead and schedule a fresh stat update at exit when needed; otherwise preserve the prior timer resume behavior.
- Defer an already queued item-transfer callback or saved-game UI rebuild until exit, before either reads inventory or rebuilds controls. Existing deferred bag-rebind behavior remains.
- Gate remaining diagnostic, hover, command, spell observer, draw and repaint entry points before initialized native getters as an additional queued-callback safeguard.

The engine's UI models are hidden, not destroyed or replaced; their normal cooldown deadline and renderer are unchanged. Previews are cancelled rather than restoring a stale armed target. Normal inventory and gear polling resumes after the shared cinematic flags clear. Profile clocks and network transport remain running because they perform no inventory scans; the capture/poll work remains paused. Intentional quest reward/item gameplay is not rewritten into a separate inventory system.

## Cross-player backpack status

The existing B/X/mouse/selection callbacks already had owner checks. The helper now also rejects a nonlocal viewer, and the three input callbacks reject remote players before resolving their hero or touching any frame. This makes the ownership boundary explicit at entry. No shared spell notification changes the open/close intent; no other player's input is intentionally routed to the local Backpack.

**The native cross-player closure is still unresolved.** This audit and its mocked remote-input tests do not prove the engine will keep the pane open. The matching first-hand native-inventory report and existing clean diagnostic map are documented in NATIVE_INVENTORY_MULTIPLAYER.md. A verified way to prevent the native engine behavior while retaining this interface has not been established. No automatic reopen, forced-key workaround, duplicate panel or local gameplay mutation is added or represented as a fix.
