## Regular-frame candidate

Recovery14 starts from Recovery12 and V25 from V23. They retain **normal .5-second cinematic UI fades**, not the unconfirmed Recovery13/V24 instant-transition experiment. Every scene's text, timing, cameras and shutdown/resume work is otherwise unchanged.

Only three functions change: QuickGear_Init, QuickGear_Reset and QuickGear_RepaintIcons. F/G's display no longer creates QuickGearDock/ItemButton/ClockFace as custom SIMPLEFRAME/SIMPLEBUTTON objects with named String/Texture children. It uses a regular FRAME root, BUTTON controls, BACKDROP icons and TEXT key labels. All creation remains in the shared initialization path; no local frame lookup/allocation or extra timer is added.

Icons, key bindings, dimensions, offsets and the original animated UI-Cooldown-Indicator model remain. The model is now a child of a regular overlay inside the same regular frame hierarchy as the button, rather than a standalone GAME_UI child anchored to a simple button. Overlay, icon, model and label controls are noninteractive so the button receives clicks. Ordinary BACKDROP icons update in place, so the old root hide/show repaint invalidation is removed. Reset destroys model children before their overlay parents and null-checks absent controls. No alternate cooldown texture animation is substituted.

This is a focused rendering candidate motivated by the captured CSimpleTop/CRenderBatch/font-batch allocator evidence. It is **not a proven crash fix**. Visual alignment, mouse clicks, key labels, icon refresh, target cursors, cooldown rendering and multiplayer cinematic acceptance require native testing. The frame types changed while their intended appearance/behavior was retained; no live screenshot comparison has been performed.
