# Modeless teleporter panel — Version E Hotfix02 / QuickUI39

2026-10-25. Native/Reforged only. Installed/hash-verified in Maps/Download/TEST: FFERPG-0.9.7.5e-Hotfix02-Forsaken.w3x and FFERPG-QuickUI39-Forsaken.w3x. Latest development base is UI39. Classic unchanged. Original release and previous candidates preserved.

The owner reports Escape still ineffective after both end-cinematic handling and direct OSKEY handling. The native Cancel button already has the standard 512 Escape binding (also found in published JASS examples, e.g. https://forum.wc3edit.net/viewtopic.php?t=7053). This is consistent with the modal dialog intercepting input; the actual engine cause has not been reproduced. Rather than another key-value guess, native Travel_Show no longer opens a modal dialog. It renders a modeless frame panel with the same destinations, order, two pages, destination hotkeys, paging and Cancel. The panel is created once at shared delayed startup; local operations only change frame presentation.

Click and keyboard requests carry the menu generation and choice through FFTravelPick sync. The shared receiver validates visibility, generation, current page, unlock state and hero before acting. Escape sends Cancel; the existing FFTravelClose handler can also hide the frame panel. Closing affects only the owner and never teleports. Chat typing cannot select destinations, and QuickGear equipment hotkeys are suppressed while travel is visible, preserving Enter/Escape chat bookkeeping. Button clicks release keyboard focus. A menu open no longer invokes DialogDisplay(...,true).

Source: experiments/Forsaken/TravelPanel.j; builder: tools/build_travel_panel.py. Native gameplay adapter applies the panel after portable travel adaptation. Classic keeps the native dialog and no frame/OSKEY/sync APIs are injected into that profile. Shared portable Travel.j refreshed to match its existing TravelPages template.
