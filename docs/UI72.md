# Capped and consolidated UI updates

Owner asks to reduce repeating work, cap background UI checks at10Hz, cache icon
updates and activate rune work only while aiming, while preserving accepted
content. Based on Hotfix02/UI71, retaining the inventory reconciliation cache.

## Scheduling

One QuickGearUITimer calls UI72_Tick every.1s. Replaces the100Hz cursor timer,
20Hz wheel/input timer,10Hz dock timer and10Hz panel timer:140 scheduled UI
callbacks/second become10. Chat recovery runs first, then key/focus handling,
dock state, conditional aim work, warning expiry, panels and development job UI.
The pre-existing inactive timer fields remain compatible with reset logic; no
dynamic timer allocation is performed from local input or preview callbacks.

Actual spell movement, combat timers and damage timings are unchanged. This
does not cap every gameplay timer or remove existing1s Chronicles/collection
maintenance. The optimization concerns the overlapping background UI work.

## Caching and active-only work

- Removed unconditional icon repaint checks from every wheel and dock tick.
  Existing equip/unequip revisions and load/job invalidation trigger the existing
  draw/paint/repaint path. A cached1s slot check catches native changes without
  reliable events. Artwork setters run only after changes.
- Backpack click fallback only polls when the native bag is visible or an item
  is being moved. Actual mouse/key events are retained.
- Cursor heartbeat work runs only while targeting or clearing the prior cursor.
  Direct input events still update its position immediately.
- Wave drawing runs only while a matching spell is armed. Mouse-move events and
  the heartbeat share a10Hz redraw limit; arming resets it for the next preview.
- Idle rune clears return before the200+ image hide operations. Active clears
  still hide every rune once. Accepted water/ice geometry and textures unchanged.
- Development DG_UIUpdate now shares the10Hz heartbeat instead of DG_Tick's
  combat timing. Rise/1000Cuts status glows still update; inactive Dragoon runes
  stop receiving repeated hide calls. DG_Tick changes only by removing its UI
  call. No motion/damage/buff formulas change.

F/G key/chat/focus recovery handlers, native mouse click/cast handling, sync
receiver, actual item casts, icon-paint workaround, warning style and preview
geometry remain unchanged. The scheduler changes when their work runs.
