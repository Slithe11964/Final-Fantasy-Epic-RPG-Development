# V31 / h UI03

Separate candidates from V29 / h UI01. V30 and h UI02 were diagnostic-only
intermediates, built but never installed. Original production h is preserved.

The owner confirmed UI Layer03's position: top-left (.812,.085), .040-square
buttons separated vertically by .046, right of command rows two and three.
Use that fixed position. Do not return to the above-command comparison point.

Only QuickGear_Init, QuickGear_Layout and QuickGear_Poll change. Shared startup
allocates one persistent native leaderboard host, preserving existing player
leaderboard associations. Its decorative title/backdrop are hidden. Existing
regular controls and animated cooldown models remain. Existing local display
poll restores only this empty host if native board switching hid it. No new
timer, item/stat getter, input path, cast/sync operation, unit/item mutation,
save/load or inventory guard is added. Reset retains the host and destroys the
existing dock children in their existing order. Cinematic gates stay intact.

Why not the scoreboard parent: the RPG deliberately hides its scoreboard and
Hunt Club while the bag is open. This host is separate from those panels.
Approach reference: Tasyen's native full-width UI host documentation,
https://www.hiveworkshop.com/threads/tasfullscreenframe.356151/ .

Native evidence: Layer01 crashed in solo startup; exact fixture path in
12:00:17 War3Log; dump fault RVA0x2c5ed4, CRenderBatch. Seven layouts were
constructed simultaneously, so that failure does not identify one layout.
Layer02 single regular WORLD_FRAME tree started/exited, but right-side display
was unsuccessful. Layer03 native Multiboard parent displayed accepted location
and exited. Layer04 invisible native Leaderboard parent displayed F/G labels
and half-filled native cooldown models; icons hid during a .5-fade native
scene and returned without a crash. Its comparison-mode restoration selected
the ABOVE-grid position due to fixture ordering, so it did NOT prove correct
post-scene coordinates. Full candidates have a single constant layout and no
comparison mode. Fixture04 uses only player0, and is not multiplayer evidence.

Both full candidates pass playable/editor compilation, startup wiring,
source/runtime/global matching and native save/load text checks. Builder
enforces all unrelated runtime functions and archive payloads unchanged;
authored description/Discord and loading credits preserved verbatim. Installed
distinct TEST/FFERPG-0.9.7.5h-UI03.w3x and TEST/FFERPG-V31.w3x.

Full-map native appearance, association restoration, Hunt/Festival switching,
bag-open visibility, real cooldown animation and multiplayer scenes remain
unverified. No stability/release promotion claim. Classic h, master and
Creature Review unchanged. Current development candidate V31, next V32.
