# V27 / Recovery16 — gear control placement and scene restoration

Owner reports Recovery15 showed about one third of a gear icon, obscured by
native UI, and the control disappeared after a cutscene. This is a visibility
failure. The report does not establish multiplayer stability or a crash cause.

Recovery16 starts from the relabeled Recovery15 workspace copy; full V27 starts
from relabeled V26. Three functions change, plus display identity strings:

- `QuickGear_Init`: the regular dock is owned by GAME_UI rather than the native
  ConsoleUIBackdrop. The dock no longer inherits that backdrop's render order
  or cinematic lifetime. Regular frame types and the original cooldown model
  remain exact.
- `QuickGear_Layout`: uses an absolute location above the command grid instead
  of a point beside native command button 7. Top-left (.748,.265), size
  (.040,.086), yields x .748–.788 and y .179–.265. It is inside the central
  .0–.8 frame band and above the console's .176 high art. Native console and
  command frames are not moved, hidden or altered.
- `C20_UIResume`: reapplies the dock's existing layout before resuming its
  existing timer. It does not show controls early, allocate frames, query gear,
  or cast/cancel. Existing ready/revision invalidation, post-scene selection
  checks and .1-second poll restore active buttons and cooldown display.

No change to item handling, input/casting/sync, polling frequency, save/load,
autosave, scene entry/content/fades/guards, gameplay, assets, jobs or creatures.
All other functions match after display-label normalization; all non-text
archive payloads match. Native backpack cross-closing is still unresolved and
the standalone backpack experiments are not integrated.
